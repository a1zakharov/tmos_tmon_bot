# Бот переключения TMOS ↔ TMON

Скелет для существующего ИИС в Т-Инвестициях. Python 3.11+, стандартная
библиотека, без сторонних зависимостей. [План разработки](DEVELOPMENT_PLAN.md).

Выполнено внутридневное исследование TMOS/TMON в точке «закрытие − 5 минут»:
[отчёт и условия](research/preclose/results/report.md),
[код и воспроизведение](research/preclose/README.md).
В версии 0.2 выбрана модель **last_quote**: последнее завершённое минутное
значение IMOEX до T−5, не старше **600 секунд** на этот момент.

Более ранний период 26.08.2020–11.07.2023 проверен с реальным фондом
LQDT и его прежним тикером VTBM: [отчёт](research/preclose_early/results/report.md),
[код и воспроизведение](research/preclose_early/README.md). Это отдельная пара
для исторического исследования; рабочая пара бота — TMOS/TMON.

## Зафиксированная логика

- Управляемая пара: **TMOS / TMON**.
- Источник сигнала сохранён из предыдущего исследования: **IMOEX**.
- **За 5 минут до окончания общей основной сессии двух фондов** фиксируется
  момент T−5. Выбирается последняя минутная свеча IMOEX, целиком завершённая
  строго до этого момента; используется её CLOSE.
- Возраст свечи на момент T−5 — не более **10 минут включительно**.
  При отсутствии подходящей свечи цель сохраняется с причиной
  `no_snapshot` или `stale_snapshot`.
- Цена ниже предыдущего минимума → целевой фонд **TMON**.
- Цена выше предыдущего максимума → целевой фонд **TMOS**.
- Цена внутри диапазона или точно на границе → сохранить прежнюю цель.
- Один снимок и одно решение на торговый день. Следующие запуски возвращают
  сохранённое решение, а не переворачивают позицию повторно.

Время берётся из `TradingSchedules` для реально найденных инструментов.
Используется пересечение **основных** сессий TMOS и TMON, включая окончание
аукциона закрытия. Вечерняя сессия не переносит момент сигнала на ночь.
Часы 18:45 или 23:45 в код не зашиты. Внутренние времена хранятся с timezone,
дата торгового дня определяется по Москве.

Если таймер запустился через 30 секунд после T−5, граница выбора свечи и расчёт
её возраста остаются привязанными к T−5. Более поздняя цена не подставляется.

**Это предварительный сигнал по минутной цене, а не подтверждённое закрытие дня.**
Результат предыдущего теста TMOS/LQDT по завершённой дневной свече нельзя
переносить на TMOS/TMON и другое время исполнения. Новый тест доступен в
`research/preclose/`; его исполнение по минутным принтам остаётся модельным.

## Что уже работает

- Чистая функция сигнала, планировщик окна, расчёт целых лотов и лимитных цен
  через `Decimal` с учётом шага цены.
- SQLite: сохранённые снимки, целевая позиция, постоянный UUID намерения;
  уникальность решения по счёту и торговому дню, атомарная запись при конкуренции.
- При первом запуске цель внутри диапазона выводится из фактически удерживаемого
  фонда. Если на первом запуске есть оба фонда, требуется отдельно выбрать
  начальное состояние. Счёт только с деньгами сам по себе не вызывает покупку.
- Адаптер **только чтения** к REST T-Invest API: закреплённый ИИС, инструменты,
  UID/лоты/шаг цены, расписание, позиции, активные заявки, стаканы и торговые статусы.
- Адаптер MOEX ISS: предыдущий дневной диапазон и ограниченный по времени
  запрос минут IMOEX. Время HTTP-ответа и обновления строки marketdata
  не выдаётся за время последнего значения индекса.
- Сохранённая цель повторно проверяется по текущим позициям, торговым статусам
  и свежим стаканам после окна сигнала, включая утро следующего торгового дня.
  Новый сигнал может заменить прежнюю цель в своё дневное окно.
- Проверки времени, свежести цены и стакана, доступности ИИС, блокировок,
  активных заявок по паре, спреда и отсутствия непокрытых позиций пары.
- Offline-демо и автоматические тесты без подключения к брокеру.

**Отправки заявок пока нет.** `mode=live` запрещён. Авторизованный транспорт
имеет allowlist только читающих методов; `PostOrder` вызвать нельзя даже
с токеном полного доступа. `execution.py` содержит интерфейс следующего этапа.
Ниже описан запуск наблюдения, а не полноценной торговли.

## Проверить локально

Из этой папки, установка пакетов не нужна:

```sh
python run.py demo
python run.py demo
python -m unittest discover -s tests -v
python research/validate_bot_model.py
```

Первый запуск фиксирует сигнал `TMON` и план продажи TMOS. Повторный возвращает
`already_decided` с тем же `intent_id`. В обоих случаях `orders_submitted=0`.
Цена и время демо взяты из искусственного `fixtures/preclose.json`, не из
текущего рынка. Демо использует отдельную базу `data/demo.sqlite3`.
Для чистого запуска новой версии можно указать отдельный файл:

```sh
python run.py demo --state /tmp/tmos-tmon-v2-demo.sqlite3
```

Сверка `validate_bot_model.py` воспроизводит 1 553 исторических решения
из обоих исследований; цели, причины и возраст наблюдений совпадают с
вариантами `last_quote`. Это проверка сигнала, а не доходности исполнителя.

Покупка в плане намеренно не имеет заранее назначенного количества: оно должно
определяться только после подтверждённой продажи и повторного чтения доступных
денег. Прогнозная выручка от ещё не исполненной заявки не считается деньгами.

## Наблюдать через API

Токен и номер ИИС задаются **локально**, в чат передавать их не нужно.
Для текущего этапа достаточно токена только для чтения нужного ИИС.

```sh
cp config.example.toml config.toml
cp .env.example .env
```

Заполнить `.env` своим токеном и точным `account_id`, затем:

```sh
set -a
. ./.env
set +a
python run.py observe --config config.toml
```

В ранее созданном `config.toml` заменить `max_quote_age_seconds = 45` на
`max_quote_age_seconds = 600`. Старое значение явно отклоняется, чтобы запуск
не продолжал прежнюю модель незаметно. Параметр
`signal_feed_verified_realtime` принимается для совместимости и больше
не влияет на решение: проверяется биржевое время выбранной минуты.
Старые записи SQLite сохраняют свои `intent_id` и блокируют повторное
решение за тот же день после обновления.

`.env`, `config.toml` и `data/` исключены из Git. Рабочая база наблюдения —
`data/state.sqlite3`, отдельно от демо. Номер счёта в журнал решения не попадает;
для разделения состояний используется его хеш. TLS-проверка сертификатов включена,
перенаправления авторизованных запросов запрещены.

Адаптеры проверены синтетическими контрактными примерами; запросы к вашему
счёту не выполнялись. С реальными данными могут потребоваться уточнения
формата ответа/торгового режима, что относится к первому этапу интеграции.

До окна программа возвращает `waiting` и рассчитанное время проверки. После
окна — `missed_window`: новое решение задним числом не создаётся.
Если цель уже сохранена, ответ дополнительно содержит текущий `execution`
с новым планом по свежим данным; прежняя цель действует и вне окна.
Окно по умолчанию — первая минута после T−5. Повторный запуск не пересчитывает
сигнал, но обновляет план. Поле `decision.plan` — исторический план на момент
решения; для текущего состояния нужно читать `execution.plan`.

При аукционе, закрытых торгах, активных заявках, недоступном или устаревшем
стакане цель сохраняется, а план получает `waiting_for_market`. Допуск
10 минут относится только к IMOEX: стакан фондов должен быть не старше
30 секунд. В режиме аукциона немедленное исполнение не предполагается.

Публичный ISS может отдавать данные с задержкой. Если подходящей минуты
не оказалось в пределах 600 секунд, бот сохраняет цель; лимит автоматически
не расширяется. Возможность получать нужные минуты вовремя требует проверки
на реальном источнике ([MOEX ISS](https://www.moex.com/a2920)).

## Состав

```text
src/rotation_bot/
  strategy.py     текущая цена против диапазона предыдущего дня
  schedule.py     общая основная сессия, закрытие минус 5 минут
  providers.py    читающие адаптеры T-Invest / MOEX ISS
  service.py      проверки, решение, подготовка плана
  state.py        SQLite и однократное решение
  execution.py    план, лоты, цены; интерфейс будущего исполнения
  domain.py       типы данных, Decimal, время
  config.py      параметры и запрет live
  cli.py          demo / observe
```

Шаблоны `deploy/rotation-observer.{service,timer}` показывают периодический
запуск наблюдения раз в 30 секунд. Они **не установлены и не активированы**;
пути `/opt`, `/etc`, пользователь службы и state directory — примеры для
этапа развёртывания. До постоянного запуска нужно добавить кеширование
метаданных/расписаний и обработку временных ошибок из плана.

Свободные деньги не инвестируются автоматически: `invest_idle_cash=false`.
Бот управляет только парой TMOS/TMON и не планирует продажу других бумаг.
Налоговый режим и вычеты не рассчитываются; `ACCOUNT_TYPE_TINKOFF_IIS`
подтверждает тип счёта, но не вид налогового вычета.

Подробные этапы, критерии готовности, восстановление частичных исполнений и
переход к реальным заявкам: [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).
